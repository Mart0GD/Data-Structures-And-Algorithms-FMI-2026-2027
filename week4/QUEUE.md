## Опашка

Опашката е новата структура от данни, която предстои да разгледаме. При нея, обратно на идеята на "стека", имаме достъп за добавяне в края на опашката (след последния елемент) и премахване на първият елемент (най-долния в колекцията). Този принцип имитира истинска опашка, като най-първият елемент влязъл в колекцията е и първият, който ще излезе. Този начин на действие се нарича "First in First out" или **FIFO**.

Ползите на опашката са много:

* Разпределение на задачи - подаване на задачи към нишки за паралелна обработка, подаване на позиция за изчисление на най-кратък път (A* алгоритъм) и т.н.
* Подаване на пакети в мрежата.
* Обхождане на графи в широчина - Breadth first search (BFS).

## Последователна реализация

Една опашка като структура от данни трябва първо на първо да включва точно две операции - **enqueue** и **dequeue**. Всяка друга операция е незадължителна и единствено помага за употребата на структурата. Единствено не трябва да позволявате произволен достъп до елементи, тъй като това ще наруши инварианта на опашката. 

Самите имплементации на опашка са много. Варират от безопасната за паралелна изпълнение [boost::lockfree::queue](https://www.boost.org/doc/libs/latest/doc/html/lockfree.html) до семплите статични академични опашки. Тук ще разгледаме втория тип, за да разберем идеята.

----

**Вариант 1**

Нека нашата опшака държим като член данни два отделни индекса - head, tail, които ще ни служат за ориентири къде да добавяме и от къде да взимаме:

~~~.cpp
class queue{
  ...
private:
  int *data;
  int head, tail;
  int capacity;
};
~~~

Тогава операциите ни за добавяне и премахване става доста лесни за имплементиране:

**Enqueue**

~~~.cpp
void enqueue(int el)
{
    if(full()) throw "error";

    data[tail] = el;
    tail++;
}
~~~

**Dequeue**

~~~.cpp
int dequeue()
{
    if(empty()) throw "error";

    int el = data[head];
    head++;

    return el;
}
~~~

---

Тук обаче има два много сериозни проблема:

**1. Празно място**

Ако имаме опашка с **4** елемента и добавим 4 елементи и извадим два имаме следния проблем:

~~~.cpp

| empty | empty | * | * |

~~~

Опашката не е пълна, но ако пробваме да добавим с: `data[tail] = el;` ще получим грешка. Тук идва на помощ **Висшата алгебра**. Вместо да си представяме опашката като линеен масив, ще си я представим като цикличен буфер!

Така операциите вече изглеждат по следния начин:

**Enqueue**

~~~.cpp
void enqueue(int el)
{
    if(full()) throw "error";

    data[tail] = el;
    tail = (tail + 1) % capacity;
}
~~~

**Dequeue**

~~~.cpp
int dequeue(int el)
{
    if(empty()) throw "error";

    int el = data[head];
    head = (head + 1) % capacity;

    return el;
}
~~~

**2. Как разграничаваме кога опашката е пълна и кога е празна?**

~~~.cpp
bool empty() { return head == tail; }
bool full()  { return head == tail; }
~~~

И двете операции проверяват за едно и също нещо. Тук решението не е толкова просто, тъй като това е лошата страна на точно тази реализация. Едно решение е да се постави булева променлива, която да се обръща да обозначава последната операция:

* 1 - добавяне
* 0 - изваждане

Така операциите ни стават:

~~~.cpp
bool empty() { return head == tail && !op; }
bool full()  { return head == tail &&  op; }
~~~

Друго по-нишово решение е да се енкодира последната операция в data. Тъй като всеки указател е подравнен на четен адрес, а всеки четен адрес завършва с 0 и така последния бит не се използва. Това е по-сложен вариант, който споменавам за пълнота!

**Вариант 2**

В този вариант няма да използваме два отделни маркера за добавяне и премахване, а ще държим само:

* От къде ни започват данните - head
* Колко са на брой - size

Така опашката ни продобива следния вид:

~~~.cpp
class queue{
  ...
private:
  int *data;
  int head, size;
  int capacity;
};
~~~

По този начин винаги можем да изчислим къде да добавим следващия елемент с `(head + size) % capacity`. Още, проверката за пълна или празна опашка стават диркетни. Така този подход е доста по-елегантен и е за предпочитане.

**Enqueue**

~~~.cpp
void enqueue(int el)
{
    if(full()) throw "error";

    int pos = (head + size) % capacity;

    data[pos] = el;
    ++size;
}
~~~

**Dequeue**

~~~.cpp
void dequeue(int el)
{
    if(empty()) throw "error";

    int el = data[head];
    head = (head + 1) % capacity;
    --size;
}
~~~
