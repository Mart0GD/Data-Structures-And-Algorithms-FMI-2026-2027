## Как компютрите пресмятат изрази?

Когато искаме да пресметнем някакъв математически израз ние хората сме свикнали да използваме така нареченият **инфиксен запис**, което значи че всяка бинарна операция се намира между двата си аргумента. 

Примери за инфиксна нотация:

~~~
Infix notation:
1) 3 + 4
2) cos(1) * (!1)
3) sqrt(1 + 2 + 3) * foo(1,2, sqrt(2))
 ~~~

В трите примера между всеки два аргумента $A$ и $B$ има оператор. Някои изрази са функции с аргументи, други са математически операции, трети са просто числа, но важното е, че операцията е между тях!

Освен тази нотация съществуват и още две - **префиксна** и **постфиксна**. Нека ги разгледаме и тях:

---

**Префиксна нотация (Полска нотация)**

Това представлява записването на аритметичните операции преди техните аргументи. Ето няколко примера:

~~~
Prefix notation
+23 --> 2 + 3
-+12BC --> 12 + B - C 
~~~

Този тип записване не е много ефективен за изпълнение, чрез компютър, тъй аргументите са след самите операции.

**Постфиксна нотация (Обратна полска нотация)**

Това, както вече се досещате, представлява записването на операциите след техните аргументи. Ето примери:

~~~
1) AB+ --> A + B
2) AB+- --> -(A + B)
3) ABfoo()C+ --> foo(A,B) + C
~~~

Този вид запис е много по-лесен за обработка от компютър и даже по-старите процесори (така наречените стекови "stack based cpu's") са използвали постфиксен запис за обработката на техните инструкции. В днешно време виртуалните машини, които превеждат кода написан на Java и C# също използват стеково базирани "виртуални процесори", за екзекуция на инструкции. 

Това всичко си има причина и това е, че обратния полски запис може да се изчисли линейно спрямо размера на израза чрез алгоритъмът, който предстои да разгледаме. 

## Алгоритъм на разпределителната гара (Shunting yard algorithm)

Този алгоритъм е изработен и доказан от един от най-великте компютърни специалисти на миналия век, а именно Едсхер Дейкстра. Идеята и екзекуцията му са много лесни за разбиране, затова нека разгледаме стъпките:

### Как работи алгоритъмът?

Нека имаме следния по-сложен израз за обработка: 

<div align = "center"> 12 + ((42 + -2) * 2 + 2) </div>

### Подготовка

За екзекуцията на алгоритъма се използват два стека:

* Стек за **token-и** - това са операциите ни (функции, бинарни операции, унарни операции, тернарни операции)
* Стек за **аргументи** - това са аргументите на израза (променливи, hard coded числа)

### Приоритет на операциите

Всяка операция ще има определен приоритет, понякога от нас, понякога от правилата на аритметиката. Най-основната подредба е:

1) Унарни операции --> `+,-`
1) Степенуване, коренуване --> `^,sqrt`
2) Умножение, деление, модулна операция --> `*,/,%`
3) Събиране, изваждане --> `+,-`
4) Отваряща скоба --> `(` (това винаги правете с най-нисък възможен приоритет)

### Ход на алгоритъма

Нека разгледаме стъпка по стъпка изпълнението на **Shunting Yard алгоритъма** върху разглеждания израз.

Всяка стъпка представлява прочитането на един символ (token) от израза. Използваме два стека:

* **`args`** — стек за операндите (аргументите), върху който се извършват самите операции;
* **`tkns`** — стек за операторите и скобите.

При срещане на оператор проверяваме приоритета на оператора, който вече се намира на върха на `tkns`. Ако е необходимо, изпълняваме операторите от стека, преди да добавим новия оператор.

---

### 1. Прочитаме `12`

Числата са операнди, затова директно ги поставяме в стека `args`.

<div align="center">

```
| 12 |     |    |
|____|     |____|
 args       tkns
```

</div>

---

### 2. Прочитаме `+`

`+` е бинарен оператор. За да определим дали трябва да изпълним оператор от `tkns`, проверяваме дали стекът не е празен и дали операторът на върха има **по-висок или равен приоритет**.

В случая стекът `tkns` е празен, затова просто добавяме `+`.

<div align="center">

```
| 12 |     |  + |
|____|     |____|
 args       tkns
```

</div>

---

### 3. Прочитаме `(`

Отварящата скоба се използва като **маркер**, който ограничава част от израза.

Тя се поставя директно в `tkns` и има най-нисък приоритет спрямо останалите оператори.

<div align="center">

```
|    |     |  ( |
| 12 |     |  + |
|____|     |____|
 args       tkns
```

</div>

---

### 4. Прочитаме `(`

Срещаме още една отваряща скоба. Тя също се поставя директно в стека `tkns`.

<div align="center">

```
|    |     |  ( |
|    |     |  ( |
| 12 |     |  + |
|____|     |____|
 args       tkns
```

</div>

---

### 5. Прочитаме `42`

Отново срещаме операнд. Поставяме `42` в стека `args`.

<div align="center">

```
|    |     |  ( |
| 42 |     |  ( |
| 12 |     |  + |
|____|     |____|
 args       tkns
```

</div>

---

### 6. Прочитаме `+`

Проверяваме оператора на върха на `tkns`. Това е `(`.

Отварящата скоба служи като граница на текущия подизраз и не позволява операторите преди нея да бъдат изпълнявани. Затова не извършваме операция и просто поставяме новия `+` в `tkns`.

<div align="center">

```
|    |     |  + |
|    |     |  ( |
| 42 |     |  ( |
| 12 |     |  + |
|____|     |____|
 args       tkns
```

</div>

---

### 7. Прочитаме `-`

Тук срещаме **унарния оператор `-`**.

Разпознаваме го като унарен, защото преди него е прочетен оператор или отваряща скоба, а не операнд. Това означава, че `-` ще работи само върху **един** операнд.

Унарният `-` има по-висок приоритет от `+`, затова не изпълняваме нищо от стека и просто го добавяме в `tkns`.

<div align="center">

```
|    |     |  - |
|    |     |  + |
|    |     |  ( |
| 42 |     |  ( |
| 12 |     |  + |
|____|     |____|
 args       tkns
```

</div>

---

### 8. Прочитаме `2`

`2` е операнд, затова го поставяме в `args`.

<div align="center">

```
|    |     |  - |
|    |     |  + |
|  2 |     |  ( |
| 42 |     |  ( |
| 12 |     |  + |
|____|     |____|
 args       tkns
```

</div>

---

### 9. Прочитаме `)`

Затварящата скоба означава край на текущия подизраз.

Затова изпълняваме операторите от `tkns`, докато не достигнем съответната отваряща скоба `(`.

#### 9.1. Изпълняваме унарния `-`

Изваждаме `-` от `tkns`.

Унарният минус взема последния операнд от `args`, обръща знака му и поставя получения резултат обратно в стека.

Тоест:

```text
-2 → 2 → -2
```

<div align="center">

```
|    |     |    |
|    |     |  + |
| -2 |     |  ( |
| 42 |     |  ( |
| 12 |     |  + |
|____|     |____|
 args       tkns
```

</div>

#### 9.2. Изпълняваме `+`

След унарния `-` на върха на `tkns` се намира `+`.

Изваждаме оператора и вземаме двата най-горни операнда от `args` — `42` и `-2`.

Изчисляваме:

```text
42 + (-2) = 40
```

Полученият резултат се връща обратно в `args`.

<div align="center">

```
|    |     |    |
|    |     |    |
|    |     |  ( |
| 40 |     |  ( |
| 12 |     |  + |
|____|     |____|
 args       tkns
```

</div>

#### 9.3. Изваждаме `(`

Продължаваме да изпълняваме операторите, докато срещнем отваряща скоба.

Изваждаме `(` от `tkns`. Самата скоба не извършва никаква операция — тя е само маркер за границата на подизраза.

<div align="center">

```
|    |     |    |
|    |     |    |
|    |     |    |
| 40 |     |  ( |
| 12 |     |  + |
|____|     |____|
 args       tkns
```

</div>

След изваждането на скобата продължаваме с четенето на израза.

### 10. Прочитаме `*`

`*` е оператор с по-висок приоритет от `+`.

На върха на `tkns` се намира `(`, който служи като граница на текущия подизраз. Затова няма оператор, който трябва да бъде изпълнен, и просто поставяме `*` в стека.

<div align="center">

```
|    |     |    |
|    |     |  * |

| 12 |     |  + |
|____|     |____|
 args       tkns
```

### 12. Прочитаме `+`

Сега срещаме оператор `+`.

На върха на `tkns` се намира `*`, който има **по-висок приоритет** от `+`. Затова първо трябва да изпълним `*`.

#### 12.1. Изпълняваме `*`

Изваждаме `*` от `tkns`.

Той взема двата най-горни операнда от `args` — `40` и `2`, и ги умножава:

```text

```

Резултатът `80` се връща обратно в `args`.

<div align="center">

```
|    |     |    |
|    |     |    |
|    |     |    |
| 80 |     |  ( |
| 12 |     |  + |
|____|     |____|
 args       tkns
```

</div>

#### 12.2. Срещаме `(`

След като `*` е изпълнен, на върха на `tkns` се намира `(`.

Тя има ролята на граница и не може да бъде изпълнена като оператор. Затова спираме обработката и поставяме новия `+` в `tkns`.

<div align="center">

```
|    |     |    |
|    |     |    |
|    |     |  + |
| 80 |     |  ( |
| 12 |     |  + |
|____|     |____|
 args       tkns
```

</div>

#### 14.1. Изпълняваме `+`

### 15. Край на израза

Достигаме края на входния израз.

В `tkns` все още има един оператор — `+`. При достигане на края на израза изпълняваме всички останали оператори в стека.

#### 15.1. Изпълняваме `+`

Изваждаме `+` от `tkns` и вземаме двата най-горни операнда от `args`:

```text
12 + 82 = 94
```

Полученият резултат се връща в `args`.

### Край на алгоритъма

След изпълнението на всички оператори в стека `args` остава само един елемент — крайният резултат:

```text
94
```

**Следователно резултатът от израза е `94`.**
