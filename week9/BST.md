# Двоично дърво за търсене (Binary Search Tree)

## Предтекст

Да кажем, че имаме огромно количество информация — **всички студенти в Софийския университет**. Това е множество, към което се добавят и от което се премахват елементи (не е фиксирано). Искаме да можем да търсим студентите по факултетен номер. Това е удобно, защото факултетните номера са цели числа, които лесно се сравняват.

Въпросът е: **каква структура от данни да използваме?**

| Структура | Добавяне | Премахване | Търсене |
|---|---|---|---|
| **1. Динамичен масив** | бързо (в края) | бавно | бавно |
| **2. Сортиран масив** | бавно | бавно | много бързо |
| **3. Свързан списък** | още по-бързо | бързо (ако е двусвързан) | изключително бавно |

Видяхме, че нито една от трите структури няма да ни свърши работа. Как да вземем най-доброто от всяка от тях — точно това ще разгледаме сега.

---

## Дефиниция

Двоичното дърво за търсене е дърво с разклоненост 2, в което всички елементи са сравними по някакъв начин и за всеки възел е изпълнен следният инвариант:

1. Лявото му поддърво съдържа само елементи, които са **по-малки** от стойността на възела.
2. Дясното му поддърво съдържа само елементи, които са **по-големи** от стойността на възела.

**Какво правим с елементите, които са равни по стойност?**

Имаме три възможности:

* Не допускаме повторения.
* Натрупваме ги в един възел (допълнително поле за броя срещания).
* Добавяме ги **само** вляво или **само** вдясно.

---

## Структура

В курса ще разглеждаме BST по следния начин: имаме корен, който е възел. Всеки възел има достъп до лявото и дясното си поддърво чрез техните корени (ако съществуват).

Примерна имплементация на **C++**:

```cpp
template <typename T>
class BST {
    struct node {
        T     data{};
        node* left  = nullptr;
        node* right = nullptr;
    };

    node* root = nullptr;

public:
    // (...)
};
```

---

## Основни операции

### Създаване — $O(1)$

```cpp
BST() : root(nullptr) {}
```

### Добавяне на елемент — $O(h)$

Обхождаме дървото и спрямо стойностите на възлите определяме в коя посока да продължим.

```cpp
void insert(node*& n, const T& el)
{
    // Намерихме празно място
    if (n == nullptr)
    {
        n = new node{el};
        return;
    }

    if (el < n->data) insert(n->left, el);   // Трябва да е вляво
    else              insert(n->right, el);  // Трябва да е вдясно
}
```

### Премахване на елемент — $O(h)$

Това е най-трудната за разбиране операция. Имаме три случая:

1. **Листо** — направо премахваме възела.
2. **Едно дете** — премахваме възела и го заместваме с детето му.
3. **Две деца** — намираме най-малкия възел в дясното поддърво (или най-големия в лявото) и го поставяме на мястото на премахвания възел.

```cpp
node* extract_min(node*& el)
{
    if (el->left) return extract_min(el->left);

    // Възелът има най-много едно дете (дясно)
    node* tmp = el;
    el = el->right;
    return tmp;
}

bool remove(node*& n, const T& el)
{
    // Елементът не съществува
    if (!n) return false;

    if (el < n->data)      return remove(n->left, el);
    else if (el > n->data) return remove(n->right, el);

    // Намерихме елемента
    node* to_delete = n;

    if (!n->left)       n = n->right;
    else if (!n->right) n = n->left;
    else
    {
        // На мястото на n поставяме:
        // най-малкия възел в дясното поддърво
        // или
        // най-големия възел в лявото поддърво
        node* m = extract_min(n->right);

        m->left  = n->left;
        m->right = n->right;
        n = m;
    }

    delete to_delete;
    return true;
}
```

### Търсене по ключ — $O(h)$

Идеята е същата като при двоичното търсене: на всяка стъпка отрязваме поддървото, в което търсеният елемент не може да се намира.

```cpp
bool find(const node* n, const T& el)
{
    if (!n) return false;                                // Няма такъв елемент

    if (el < n->data)      return find(n->left, el);     // По-малък
    else if (el > n->data) return find(n->right, el);    // По-голям
    else                   return true;                  // Открихме го
}
```

> [!IMPORTANT]
> $h$ е височината на дървото. В най-добрия случай тя е $\log_2 n$, но ако дървото не е добре построено, може да достигне $n$.
>
> При `insert` и `remove` подаваме указателя по референция, за да променяме самия указател в дървото, а не негово копие.

## Незадължителни операции

### Обхождане — $O(n)$

При двоичното дърво за търсене имаме различни стратегии за обхождане, които се делят на два типа:

* **DFS** (Depth First Search) — обхождане в дълбочина
* **BFS** (Breadth First Search) — обхождане в ширина

#### DFS: ЛКД (ляво-корен-дясно) — `inorder traversal`

```cpp
// Приложения: извличане на елементите в сортиран ред;
// извеждане на израз от абстрактно синтактично дърво (AST) в инфиксен запис
// Време O(n), памет O(h)
void inorder(const node* n)
{
    if (!n) return;

    inorder(n->left);
    std::cout << n->data << ' ';
    inorder(n->right);
}
```

#### DFS: ЛДК (ляво-дясно-корен) — `postorder traversal`

```cpp
// Приложения: изтриване на дърво (децата се освобождават преди родителя);
// изчисляване на аритметични изрази в AST
// Време O(n), памет O(h)
void postorder(const node* n)
{
    if (!n) return;

    postorder(n->left);
    postorder(n->right);
    std::cout << n->data << ' ';
}
```

#### DFS: КЛД (корен-ляво-дясно) — `preorder traversal`

```cpp
// Приложения: копиране на дърво; сериализация,
// от която дървото се възстановява в същата форма
// Време O(n), памет O(h)
void preorder(const node* n)
{
    if (!n) return;

    std::cout << n->data << ' ';
    preorder(n->left);
    preorder(n->right);
}
```

#### BFS (обхождане по нива)

```cpp
// Приложения: сериализация, изчисляване на суми, тежест и др. по нива
// Време O(n), памет O(q), където q е броят възли в най-широкото ниво
void bfs()
{
    if (!root) return;

    std::queue<const node*> levels;
    levels.push(root);
    levels.push(nullptr);  // Маркер за край на ниво

    while (true)
    {
        const node* curr = levels.front();
        levels.pop();

        if (curr == nullptr)
        {
            std::cout << '\n';
            if (levels.empty()) break;
            levels.push(nullptr);
        }
        else
        {
            std::cout << curr->data << ' ';

            if (curr->left)  levels.push(curr->left);
            if (curr->right) levels.push(curr->right);
        }
    }
}
```

### Височина — $O(n)$

```cpp
// Взимаме по-голямата от височините на лявото и дясното поддърво
int height(const node* n)
{
    if (!n) return 0;
    return 1 + std::max(height(n->left), height(n->right));
}
```

### Брой елементи — $O(n)$

```cpp
int weight(const node* n)
{
    if (!n) return 0;
    return 1 + weight(n->left) + weight(n->right);
}
```

### Балансираност — $O(n^2)$ в най-лошия случай

```cpp
// Балансирано е дърво, в което за всеки възел височините
// на лявото и дясното поддърво се различават с най-много 1
bool balanced(const node* n)
{
    if (!n) return true;
    return std::abs(height(n->left) - height(n->right)) <= 1
        && balanced(n->left)
        && balanced(n->right);
}
```

## Проблеми

Колкото и добро да изглежда на пръв поглед двоичното дърво за търсене, то има своите недостатъци:

* Дървото лесно се изражда при последователно добавяне на нарастващи или намаляващи елементи. Тогава то се превръща в едносвързан списък, а търсенето и добавянето стават линейни.
* Имаме лоша локалност — елементите са разпръснати в паметта.
* При автоматично балансиране чрез AVL или червено-черни (Red-Black) дървета операциите по добавяне и премахване се усложняват и забавят, в замяна на гарантирана логаритмична височина и бързо търсене.

## Балансиране

За да избегнем израждането на дървото в списък, се използват т.нар. балансиращи алгоритми. Балансирането може да бъде както по тежест, така и по височина, в зависимост от търсения ефект.

Алгоритмите се делят на два типа:

* **Офлайн** — извършват се еднократно, при създаване или в даден момент, тъй като са бавни, но постигат перфектен баланс.
* **Онлайн** — извършват се допълнителни проверки и операции при всяко добавяне и премахване. Не се постига перфектен баланс, но балансирането става по време на работа, без да се спира програмата.

### Алгоритъм за статичен баланс

Ако дървото се изроди прекалено много, можем да го обходим в стил ЛКД и да извлечем възлите в сортиран вид. След това по метода на двоичното търсене построяваме дървото наново.

Примерна имплементация на C++:

```cpp
void static_balance()
{
    if (root)
    {
        std::vector<node*> nodes_sorted;
        extract_nodes(root, nodes_sorted);  // ЛКД обхождане в масив
        root = build_PBT(nodes_sorted, 0, nodes_sorted.size());
    }
}

void extract_nodes(node* n, std::vector<node*>& nodes)
{
    if (!n) return;

    extract_nodes(n->left, nodes);
    nodes.push_back(n);
    extract_nodes(n->right, nodes);
}

// Построява перфектно балансирано дърво от nodes[start, end)
node* build_PBT(std::vector<node*>& nodes, std::size_t start, std::size_t end)
{
    if (start >= end) return nullptr;

    std::size_t mid = start + (end - start) / 2;
    node* root = nodes[mid];

    root->left  = build_PBT(nodes, start, mid);
    root->right = build_PBT(nodes, mid + 1, end);

    return root;
}
```
